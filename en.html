Automatic BEV Transformation
Review and Change Request

This document compares the existing four-parameter perspective transformation with the current automatic calibration method and proposes constraints and UI changes to prevent unintended vehicle rotation.

Scope: Front Camera BEVOutput: 1224 × 1024Key issue: 6-parameter vs 8-parameter

1. Executive Summary

Four existing inputs

The current model uses yaw, pitch, width, length.

Six calculated matrix values

The horizontal trapezoid constraint makes h21 and h31 zero.

Eight values in the automatic matrix

The four user-selected points form an unrestricted quadrilateral.

The existing matrix structure must remain

The top and bottom edges must stay parallel to the image x-axis.

A constrained trapezoid UI is required

The UI must preserve the horizontal constraint while points are edited.

4. Difference in the Current Automatic Transformation

Current automatic matrix
H =
[-0.357376940  -0.905386407  1007.356816135]
[-0.020639505  -1.892168148  1784.690500771]
[-0.000068654  -0.001458344     1.000000000]

Cause

The current program treats the four selected points as an unrestricted quadrilateral. Because the y values on the top and bottom edges can differ, a full eight-degree-of-freedom homography is generated.

h21 and h31 are nonzero, allowing small point-selection errors and quadrilateral tilt to affect the rotation of the entire result.

Assessment: Even though the vehicle and board were physically aligned according to the calibration standard, the vehicle centerline does not align with the BEV vertical axis. The result is therefore incompatible with the required existing transformation behavior.

5. Required Automatic Transformation

The transformation region must remain a horizontal trapezoid even when the user selects four points.

The two top points must have the same y value, and the two bottom points must also have the same y value. The transformation matrix must then be recalculated from the corrected points.

Required matrix
[ h11  h12  h13 ]
[  0   h22  h23 ]
[  0   h32   1  ]

Validation

abs(h21) < epsilon
abs(h31) < epsilon

Use a numerical tolerance. Do not calculate a general matrix and forcibly overwrite the two values with zero; correct the input trapezoid first and then recalculate the matrix.

7. Change Requirements

The two top points must share one y coordinate, and the two bottom points must share one y coordinate.
The horizontal trapezoid constraint must remain active after every point edit.
The calculated matrix must satisfy h21≈0 and h31≈0.
The existing inverse calculation must generate yaw, pitch, width, and length.
The vehicle centerline, board longitudinal axis, and BEV vertical axis must coincide.
The board must appear as a 240 px × 240 px square at the lower center of the ROI.

8. Our Position and Proposal

We agree that a general 3×3 homography has eight degrees of freedom and cannot be converted exactly into the existing four parameters. However, we do not believe the solution is to remove the four parameters and require the existing software to accept a raw 3×3 matrix.

Why the four parameters should remain

  • They are intuitive and meaningful to field operators.
  • Operators can identify abnormal values and fine-tune calibration.
  • They preserve compatibility with existing equipment, configuration files, inverse calculations, and operating procedures.
  • They represent the physical rule that the vehicle and board are parallel.
  • They restrict unnecessary rotational freedom and prevent vehicle rotation distortion.

Concerns with direct matrix input

  • Field operators cannot easily interpret individual values or determine valid ranges.
  • Corner-selection errors and tilt can affect the full transformed image.
  • A visibly rotated vehicle may still be represented by a mathematically valid matrix.
  • The existing software and data structures would need to change.
  • Calibration values become difficult to compare and manage across vehicles.

Proposal

The mismatch is caused not by the four-parameter model itself, but by the automatic calibration program generating an unrestricted eight-degree-of-freedom matrix.

Instead of changing the existing software to accept a full matrix, constrain the selected four points to a horizontal trapezoid and generate a matrix and four parameters that are compatible with the existing model.

Do not adapt the existing system to an 8-DOF matrix.
Adapt the automatic calibration result to the existing 4-parameter model.
Final request: Do not calculate an 8-DOF matrix first and then approximate four parameters or require manual readjustment. Apply the existing model constraints from the initial four-point selection and directly generate a compatible result.
